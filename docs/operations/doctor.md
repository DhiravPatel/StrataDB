# `strata doctor` — read-only diagnostics (spec §22.3)

```
strata doctor --data-dir D [--config strata.toml] [--deep] [--max-backup-age-hours 168] [--key-file K]
```

Doctor never modifies the data directory: it does not take the writer lock,
replay the WAL, delete files or rewrite indexes. `tests/doctor.rs` proves this
by snapshotting every file (contents and mode) before and after a run. The
output is one JSON document `{"checks":[{"check","status","detail"}…]}`, where
`status` is `ok`, `warn` or `fail`. The exit code is non-zero if any check
fails. Secret values (keys, tokens, TLS private keys) are never printed; only
paths, modes and dates are.

Run it first in any incident (`docs/runbooks/recovery.md`), after upgrades,
and from monitoring (for example daily with `--config`, alerting on `warn`).

## Checks

| check | fails when | warns when |
|---|---|---|
| `version` | — | — (reports formats this binary reads) |
| `data_dir` | missing / cannot stat | mode grants group/other access (should be 0700) |
| `permissions` | — | group/other-accessible files, symlinks |
| `config` (with `--config`) | file does not parse or does not validate | — |
| `memory` | — | memtable × 2 + `max_concurrent_queries` × 256 MiB query budget exceeds physical RAM |
| `lock` | — | another process holds the writer lock (results may be mid-flush) |
| `disk` | — | free space below the default write reserve |
| `encryption` | keyring cannot be opened with the given key | encrypted but no `--key-file` (manifest/segment checks are skipped), or a key given for an unencrypted directory |
| `manifest`, `format_compatibility` | undecodable, or a format newer than this binary | — |
| `segments` | checksum, footer, Bloom or n-gram extension fails verification | — |
| `indexes` (with `--deep`) | a Bloom or n-gram filter would skip a segment that contains a matching value (false negative) | — |
| `unreferenced` | — | quarantined files present |
| `wal` | damage that may hold acknowledged data | torn tail (normal after a crash) |
| `fd_limit` | soft `RLIMIT_NOFILE` < segments + WAL segments + 256 | limit < 4× that |
| `clock` | — | a segment was created in the future (clock moved backwards) |
| `tls` (with `--config` and `[tls]`) | cert/key does not load, or the certificate has expired | expires within 30 days; key file readable by group/other |
| `backups` (with `--config` and `[backup] dir`) | — | no backup, an unreadable `BACKUP` manifest, or the newest is older than `--max-backup-age-hours` |
| `tokens` | — | token store mode is not 600 |
| `audit` | hash chain broken | — |

### Notes

- **Deep index verification** (`--deep`) reads every row, so it costs as
  much as a full scan. To fix a failure, run `strata indexes rebuild`, which
  rewrites the segment while the server is stopped.
- **File descriptor limit.** The limit checked is the one in effect for the
  `strata` process. Run doctor under the same service manager settings as the
  server (systemd `LimitNOFILE=65536`, or `ulimit -n` in the container
  entrypoint). On Linux the limit is read from `/proc/self/limits`; elsewhere
  from the POSIX `ulimit -n`.
- **Memory.** This is an upper bound on the engine's own budgets, not a
  measurement. The OS page cache and the allocator's overhead come on top.
- **TLS expiry** is read from the first certificate in the PEM chain, which is
  the leaf certificate. The DER parser is minimal and bounded, and it is
  checked against certificates generated by `rcgen` (UTCTime and
  GeneralizedTime).
- **Not checked (single-node build):** cluster connectivity and clock skew
  against peers. Both arrive with distributed mode (Phases 7–8). The `clock`
  check only detects local time moving backwards.
