# Storage I/O engine and segment file cache: overhead check (HW-REF-7)

## Summary
Segment, manifest and backup reads now go through `stratadb_common::io`:
- an `IoEngine` trait with submit/complete semantics;
- a portable `pread` backend with an LRU of open files bounded by a
  descriptor budget, identity-checked reopens, short-read resubmission, and
  one retry on a failed read;
- a deterministic `sim` backend for fault injection.

This report checks that the extra layer costs nothing measurable on the
query path. Each segment read now takes a short mutex on the file cache.

**Result:** in 3 interleaved foreground pairs of
`benchmarks/scenarios/concurrency.toml`, single-query medians and all load
results are within run-to-run noise. No regression is visible on this
machine, which is HW-REF-7, a shared laptop with no capacity claim.

## Correctness evidence
- `stratadb_common::io::tests`:
  - One conformance suite runs against the `pread`, `sim` and
    fault-decorator backends: reads, batches, past-end reads, writes,
    missing files.
  - Descriptor budget: 40 files under a budget of 8, transparent reopen.
  - A replaced file (new inode at the same path) is reported, never read.
  - Short reads are resubmitted; one EIO is retried; two EIOs give an error
    naming the file, offset and length; a file that shrank is detected.
  - Write faults: short write, ENOSPC, fsync EIO reported once with the
    dirty data lost at a crash (Linux semantics), latency spikes.
  - Crash model (200 seeds): the durable prefix always survives; unsynced
    writes are lost, torn at 512-byte sectors, or reordered;
    deterministic per seed.
- `stratadb-query/tests/io_faults.rs`, under real queries:
  - short reads and one EIO give identical results;
  - persistent EIO on one segment fails the query, naming that segment
    file, with no partial result;
  - 30 segments under a budget of 8 descriptors: correct counts at
    parallelism 1 and 8, at most 8 files open.
- `metrics_histograms_and_query_outcomes`: `strata_io_*` metrics.
- `max_open_files_setting`: config validation.
